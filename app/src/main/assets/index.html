What this page is for

Every button above crosses the boundary between the web view and the app. The page calls a method, Kotlin handles it, and anything that comes back arrives as a JSON string. Nothing here talks to a network.

Why the bridge returns a string

An @JavascriptInterface method can only hand back a primitive or a String, so the device profile is serialised with org.json and parsed on this side. That is the one real difference from the iOS build, where a WKScriptMessageHandler reply resolves a promise.

Why this page is long

A single screenshot only proves that the screen opened. This page runs past the bottom of the emulator on purpose, so the capture has to scroll and stitch the parts together before it posts anything.

What a scrolled capture has to get right

It must stop when the page stops moving rather than after a fixed number of flicks, and it must not post the same frame twice. Both are easy to get wrong and obvious in the result.

The Legacy screen

The Legacy action in the toolbar opens a second screen, two taps deep. Capturing it proves a recipe can navigate, not just launch the app and shoot.
